> 상태: 로드맵 2단계("tester 에이전트, 커버리지 게이트") 작업 시 구체화 예정. 지금은 인터페이스 자리표시자.

## 예정 입력
- `testcases/**/*.md`: TC-ID, 대상 계층, 탐색 힌트, Given/When/Then
- 변경된 소스 파일 목록 (diff 모드) 또는 전체 소스 (full 모드)

## 예정 작업 순서 (초안)
1. 각 테스트케이스의 "탐색 힌트"로 대상 레포에서 해당 클래스/메서드를 찾는다.
2. 이미 해당 시나리오를 커버하는 기존 테스트가 있는지 먼저 확인한다 (중복 생성 방지).
3. Given/When/Then을 테스트 코드(JUnit5 + Mockito 등 레포의 기존 스택)로 변환한다.
4. 생성한 테스트를 실행한다. 컴파일 실패 또는 기존 테스트를 깨뜨리면 해당 테스트는 폐기하고 실패 사유만 리포트한다.
5. JaCoCo로 변경 코드 커버리지 증분을, PIT로 뮤테이션 스코어를 함께 리포트한다 (설계서 9장 참고).

## 출력 (예정)
테스트 실행 결과를 `TestResult`/`CoverageReport` 형태로 코어 엔진에 반환. 세부 스키마는 2단계에서 `schema/`에 추가한다.
